# GLOCAL Showcase

A React + Vite portfolio site for GLOCAL Foundation projects: reports, datasets, interactive tools, and events.

## Getting started

```bash
npm ci
npm run dev      # local development server
npm run lint     # lint the codebase
npm run build    # production build -> dist/
```

## Add a project

Use the showcase's [Submit a Project tool](https://glocal-open-source.github.io/showcase/#/submit) to create a project package, then import it with:

```bash
npm run project:import -- path/to/project-package-name.json
```

The importer validates the package, generates the project page, saves its thumbnail, assigns the next ID, and updates the project list. Use `--dry-run` to preview an import without changing files.

See [CONTRIBUTING.md](CONTRIBUTING.md) for the complete submission, review, cohort, bulk-import, and pull-request workflows.

## Querying project data

The site is static — there's no server or database — so `src/api/projects.js` is a plain module that queries the in-memory project list from `src/data/projects.js`. Import it in any component:

```js
import { queryProjects, getProject, getProjectStats, parseFilterParams, getFilterOptions } from "../api/projects";
```

### Filtering

`queryProjects(filters)` returns the projects matching every filter given (AND-combined). All filters are optional.

```js
queryProjects({ cohort: "NYSN" });                     // exact value
queryProjects({ type: "data,report" });                 // comma-separated = OR within the field
queryProjects({ type: ["data", "report"] });             // same, as an array
queryProjects({ tag: "civic-tech" });
queryProjects({ q: "voting" });                          // free-text match against title + description
queryProjects({ title: "VoteMatch" });                    // any other project field works too, exact match
queryProjects({ cohort: "NYSN", province: "ab" });        // combine filters
```

`getProject(id)` returns a single project by id, or `null`.

### Filter slugs

`type`, `cohort`, `category`, and `province` each accept either the exact value or a URL-friendly slug — useful for query-string filters like `?province=ab&cohort=admin`:

| Field      | Accepts                                          |
|------------|---------------------------------------------------|
| `type`     | exact value (already slug-shaped, e.g. `data`)     |
| `cohort`   | exact value or slug, e.g. `Microgrant 2024` / `microgrant-2024` |
| `category` | exact value or slug, e.g. `Climate Change` / `climate-change` |
| `province` | 2-letter code (`ab`), tag (`alberta`), or display name (`Alberta`) |

Call `getFilterOptions()` to list every valid value and its slug per field — handy for building filter UI.

To go straight from a query string to a filters object, use `parseFilterParams`:

```js
parseFilterParams("?province=ab&cohort=Admin&q=vote");
// => { ids: [], types: [], cohorts: ["Admin"], categories: [], provinces: ["ab"], tags: [], q: "vote" }

queryProjects(parseFilterParams(window.location.search));
```

It also accepts a `URLSearchParams` instance directly.

### Stats

`getProjectStats(filters)` counts matching projects, optionally broken down by one or more fields via `groupBy`:

```js
getProjectStats({});
// => { total: 392 }

getProjectStats({ groupBy: "cohort" });
// => { total: 392, cohort: { Admin: 21, NYSN: 13, ... } }

getProjectStats({ province: "ab", groupBy: ["category", "type"] });
// => counts scoped to Alberta projects, broken down by category and by type
```

`groupBy: "province"` and `groupBy: "tags"` are also supported and aggregate across each project's full tag/province list rather than a single field.

### HTTP API (for querying from another project)

`src/api/projects.js` only runs inside this app's bundle — it's not reachable from outside. To query the project data from a separate project, use the Cloudflare Worker in `worker/index.js`, which serves the same filtering and stats logic over HTTP with CORS enabled for any origin.

It runs over a plain-JSON snapshot of the project data (`public/data/projects.json`, generated by `npm run data:json`) rather than `src/data/projects.js` directly, so the Worker bundle doesn't have to pull in React or the ~300 lazily-loaded project page components.

```bash
npx wrangler login     # one-time, authorizes the CLI against your Cloudflare account
npm run worker:dev      # regenerates public/data/projects.json, then serves the worker locally
npm run worker:deploy   # regenerates public/data/projects.json, then deploys with wrangler
```

`wrangler deploy` prints the live URL on success — with the worker name in `wrangler.toml` (`glocal-showcase-projects-api`) it will look like:

```text
https://glocal-showcase-projects-api.<your-subdomain>.workers.dev
```

(`<your-subdomain>` is assigned by your Cloudflare account the first time you deploy any Worker — check the Workers dashboard if you're not sure what yours is.)

Endpoints:

| Route             | Description |
|--------------------|-------------|
| `GET /projects`      | Query projects — same filters as `queryProjects` (`type`, `cohort`, `category`, `province`, `tag`, `id`, `q`), passed as query params. Returns `{ total, results }`. |
| `GET /projects/:id`  | A single project by id, or `404`. |
| `GET /stats`          | Same filters as `/projects`, plus repeatable/comma-separated `groupBy`. Returns the same shape as `getProjectStats`. |

So **all projects from Alberta**, from any other project or `curl`, is:

```text
https://glocal-showcase-projects-api.<your-subdomain>.workers.dev/projects?province=ab
```

and Alberta's project count broken down by category:

```text
https://glocal-showcase-projects-api.<your-subdomain>.workers.dev/stats?province=ab&groupBy=category
```

## Project structure

```text
public/
  thumbnails/   Project card images
  content/      PDFs, HTML embeds, and local videos
  data/
    projects.json  Generated JSON snapshot of the project data (git-ignored)
src/
  api/
    projects.js Query/filter/stats module over the project data (in-app)
    query.js    Shared filter/stats logic (used by projects.js and the worker)
  components/   Shared interface components
  content/      Per-project React overview pages
  data/
    projects.js Master project list
scripts/
  import-project.mjs        Project-package importer
  generate-projects-json.mjs Regenerates public/data/projects.json
worker/
  index.js      Cloudflare Worker — HTTP API over the project data
wrangler.toml   Cloudflare Worker config
```

## Deployment

```bash
npm run deploy
```

The site (GitHub Pages) and the projects API (Cloudflare Worker, see [Querying project data](#querying-project-data)) deploy separately — `npm run deploy` only publishes the static site.

This builds the site and publishes `dist/` to the `gh-pages` branch.
